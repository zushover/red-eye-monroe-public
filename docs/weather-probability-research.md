# 机场日最高温概率模型：研究依据与离线升级方案

状态：研究设计，**未接入实盘**。红眼曼罗的 STOP/禁用状态不得因运行本方案改变。更新：2026-09-16。

## 1. 目标变量必须先定义对

每条样本以 `(结算站 ICAO, 站点当地日期, Polymarket 原始温度档)` 为唯一键。目标是结算规则所用来源的当日日最高温，不是城市 App 的最高温，也不是某次 METAR 的气温。保留结算来源、时区、摄氏/华氏、档位上下界、是否含端点、数据修订及最终判定时间。METAR 逐时观测只是盘中证据；若最终结算用的日高包含整点间极值，仅凭逐时 METAR 不能把低档概率硬设为零。NOAA 的 ASOS 手册明确说明小时、六小时和日最高温的记录粒度不同。[NOAA ASOS 手册](https://www.weather.gov/media/asos/aum-toc.pdf)

模型输出两个不同量：`P(Y∈档位 | 决策时已知信息)` 是结算概率；`P(未来可成交 Bid 达到目标 | 当前盘口和信息)` 是交易退出概率。二者不能互相代替。“模型中心为26°C”也不等于“26°C档胜率26%”。

## 2. 现状盘点与不能夸大的部分

- `internal/model/model.go`：两个显式全球预报中心、城市偏差/权重、盘中 METAR 轨迹修正、正态或集合核分布、按阶段缩小方差；一些收敛系数和阈值目前是手工指定。
- `configs/city-weather-calibration.json` 与 `data/backtest/city-model-research/`：按城市的历史预报—METAR 日高拟合。研究比较了40种候选，47站完成拟合，29站通过相对基准的研究门槛；通过不等于实盘批准。
- 历史 `previous_day1` 是逐有效小时的滚动24小时提前量，不是固定在前夜、06:00或09:00发布的预报版本。不能拿它冒充盘中回测。
- `data/backtest/calibration-report.json` 仅有2个独立目标日的早期市场结算样本，远不足以验证概率校准或盈利。
- 当前模型的“可信度”包含轨迹拟合启发式，与真正的分档可靠性、Brier/对数损失不是同一个指标。

## 3. 优先采用的研究方法

| 方法 | 对本任务的可用部分 | 决策 |
|---|---|---|
| NOAA 站点 MOS | 全球模式、历史观测和地理信息做站点偏差修正；是我们城市层的直接先例。[NOAA MDL](https://vlab.noaa.gov/web/mdl/mos) | **优先**，先建层级/收缩城市模型 |
| EMOS / 非齐次回归 | 将集合均值与分歧映射成预测分布的均值和尺度，再用 CRPS/似然拟合；ECMWF 的校准综述概括了偏差、离散度和锐度的权衡。[ECMWF综述](https://www.ecmwf.int/sites/default/files/elibrary/2014/9607-calibration-medium-range-weather-forecasts.pdf) | **优先**，替换手工方差系数的离线候选 |
| 时序 EMOS | 对站点温度误差引入序列结构；适合有历史预报版本和连续实况后研究早晨/盘中残差。[论文](https://arxiv.org/abs/2402.00555) | **第二阶段**，须先补逐时版本数据 |
| WeatherBench 2 | 开源概率评估框架，含 CRPS、Brier、ignorance/log score 等；其全球格点评分不能直接证明机场整数档表现。[代码](https://github.com/google-research/weatherbench2) | 借用指标与评估纪律，不直接部署全球模型 |
| GraphCast/WeatherNext、ECMWF Anemoi | 提供全球预报和训练/推理框架，但格点模型仍需站点订正、精确日期/档位映射与概率校准。[WeatherNext](https://github.com/google-deepmind/weathernext)、[Anemoi](https://github.com/ecmwf/anemoi) | 作为可选预报信源，不在本机从头训练全球模型 |
| AI2ES 站点误差学习 | 用最近约30小时预报及实况预测站点未来小时误差，思路适合盘中剩余升温。[项目](https://github.com/ai2es/forecast_error_hrrr) | 借鉴特征工程；先用小模型验证 |

## 4. 推荐数学框架（仅离线原型）

设 `Y_s,d` 为站点 `s` 当地日 `d` 的最终结算日高，`t` 为决策时刻；所有输入的**发布时间与可得时间**必须早于 `t`。

### 4.1 前夜/早晨先验

以 ECMWF、GFS、best-match 或新增独立源的目标日峰值 `x_j` 为输入：

`μ_prior = α_region + α_station(shrunk) + Σ_j w_j x_j + seasonal + lead_time`。

`σ_prior² = softplus(β0 + β1·ensemble_spread² + β2·cloud/rain_regime + β3·lead_time)`。

站点参数用区域共享先验或惩罚项向区域均值收缩；样本少的城市不能从少量误差中得到极端权重。天气源高度相关，不能把“三信源一致”当成三次独立证据。分布候选为正态、Student-t（厚尾）、校准集合核密度；按独立日期评估，不默认某种分布必优。

### 4.2 06:00以后条件化

将过去同站实况与**同一预报版本**对应小时温度对齐，计算残差水平、趋势和近3小时升温速率；加入云量、降雨、露点、风向切换、海风/地形类型。学习 `R_t = Y_s,d − max_observed_s,d,t` 的**剩余升温分布**，而不是仅把日高中心做线性修正。更新后 `Y=max_observed+R_t`，但因 METAR 与官方日高粒度不同，保留由历史测得的观测—结算差异核，不能用错误的硬下限。

可用分位数回归、离散生存/危险率模型或条件核分布拟合 `R_t`；每个本地阶段单独验证：00–06、06–09、09–12、12–峰值、峰值后。峰值后仍需观测覆盖和官方数据修订状态，不能仅凭“天黑”把概率压成100%。

### 4.3 原始市场档位积分

每个档位概率是预测分布在**该市场原始上下界**上的积分。F盘先在华氏空间按实盘两度档积分，不能先四舍五入摄氏度再贴到F盘。所有档位（含上下尾）概率和应为1；边界按规则处理。单独统计 `P(METAR日高 ≠ 结算日高)`，避免伪确定性。

## 5. 必须采集的数据形状

1. 每个源的 `issued_at`、`available_at`、`valid_at`、站点经纬度、模型运行编号、每小时温度及云雨风变量；同一天多次预报版本不可覆盖。
2. METAR 原始报文及观测/接收时间、十分之一温度、小时/六小时极值字段；正式结算值与修订记录分表保存。
3. Polymarket 原始档位与规则、每次 Bid/Ask/深度快照、成交费率、实际成交与撤单。天气概率回测和交易收益回测分开。
4. 保存每次决策时完整可见信息。缺少历史 `issued_at` 的样本只能做T−24研究，不能进盘中模型训练。

## 6. 回测和上线门槛

- 以**站点当地目标日**为分组做严格前向滚动验证；同一天的多个温度档不得跨训练/测试泄漏。城市选型、系数调优与最终测试使用三层独立区间，已反复查看的2024–2025留出集不再称为“未触碰测试”。
- 基线至少包括当前线上模型、单一最佳信源、市场共识（市场仅作交易基线，不混入纯天气模型输入）；报告 MAE、CRPS、原始档位多类别 Brier、对数损失、可靠性图、分阶段/城市/季节样本数与置信区间。
- 模型升级须在**真正新日期**上同时改善分档 proper score 与校准，尾档不得恶化显著；交易层还须有可成交 Bid/Ask、深度与费用的独立前向回放。只降低 MAE 或只增加“机会”数量不够。
- 任何新模型先只写影子预测和回测，不修改 `CalibrationReady`、实盘开仓阈值、风险限额或自动重启。通过门槛后再单独审核发布。

## 7. 下一步最小实验

先固定历史数据清单与时间泄漏检查；再在已有T−24配对数据上比较“当前城市模型 vs 层级收缩 EMOS vs 厚尾/残差核”，输出站点和总体的分档可靠性与置信区间。随后采集足量逐小时**历史预报版本**及结算日高，才训练剩余升温阶段模型。不要用当前少量市场赢家样本硬训练或宣称模型已可获利。
